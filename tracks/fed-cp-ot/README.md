## Pipeline

This track implements provenance checks, vintage storage, streaming VOL ingestion,
weekly aggregation, exact step-quantile metrics, burn-in replication, and a static
placeholder. Candidate fitting and the confirmatory OOS harness are a later PR.

Run from this directory with a Python 3.13 venv built from `requirements.txt` (NumPy 2.5.3,
pandas 3.0.6, pytest; standard library otherwise):

```sh
python -m pytest -q
python -m pytest -q -m realdata
python -m pytest -q -m 'not realdata'
```

The prereg location is fixed at the committed `tracks/fed-cp-ot/prereg/`.

```sh
python -m fed_cp_ot.ingest seed /workspace/research/fed_cp_ot_prereg/raw/FRB_CP_xml.zip
python -m fed_cp_ot.ingest fetch
python -m fed_cp_ot.ingest list
python -m fed_cp_ot.burnin_checks --zip /workspace/research/fed_cp_ot_prereg/raw/FRB_CP_xml.zip
python -m fed_cp_ot.app --zip /workspace/research/fed_cp_ot_prereg/raw/FRB_CP_xml.zip
```

`burnin_checks --csv PATH` selects a CSV explicitly; its pinned hash is required.
The default search is `/workspace/research/fed_cp_ot_prereg/raw/fed_cp_volume_stats_by_maturity.csv`,
then `data/fed_cp_volume_stats_by_maturity.csv`. Zip SHA256 and equality to the
pinned research vintage are printed. `--compare-to-pinned --zip NEWER.zip` reports
changed burn-in series-dates and whether the replicated numbers still match;
it creates no trial and makes no gate decision. Both vintages withhold post-wall values.

`ingest fetch` downloads the public Fed zip using urllib; `ingest list` prints
manifest records. Tests never use the network. Fast tests copy prereg files into
temporary directories from committed pins, without requiring the research directory.
Real-data tests parse once per session and skip if neither the research zip nor
a cached vintage with its pinned hash exists.

- `fed_cp_ot/preflight.py`: checks all seven pinned files, PIN references and
  design semantics. Only issued immutable Provenance objects can open a loader.
- `ingest.py`, `parse.py`, `csv_check.py`, `vintages.py`: immutable zip vintages,
  append-only manifest, namespace-independent parsing, CSV validation and diffs.
  `diff_vintages` returns a report; `append_diff` explicitly persists it.
- `weekly.py`, `metric.py`: Monday–Friday sums, valid-day requirements, exact W2²,
  decomposition, quantile barycenters, and ALR zero replacement.
- `forecast.py`, `trials.py`: persistence interface, origin-only features,
  hash-chained forward log and approval-gated trial accounting. Forward-log keys
  are (target, type, model); outcomes are unique by (target, type). Origins must
  be Fridays and targets exactly seven days later. Inputs end at the origin,
  forecasts precede outcome availability, and no forecast can be added after
  an outcome. Outcome storage and scoring both enforce the wall. Records are
  append-only and hash-chained; duplicate keys and tampering are refused.
- `burnin_checks.py`: replicates the requested printed descriptive numbers to
  ten decimal places. No half-split, gate decisions, or power simulations run.
- `app.py`: deterministic inline-CSS page at `docs/tracks/fed-cp-ot/app/index.html`.
  Without a zip it uses conspicuously labelled synthetic data. An explicit bad
  zip or failed preflight raises rather than silently falling back.
- `data/`: ignored vintages, manifest, diff records, forward log and
  `burnin_checks.json`. The CSV search order is described above. `trials.jsonl` is outside the cache and is not created by burn-in.

The source is the [Federal Reserve CP XML zip](https://www.federalreserve.gov/releases/cp/data/FRB_CP_xml.zip),
member `CP_data.xml`. The 60 VOL series distinguish NAA from NA2; the derived CSV
loses their tier labels and is used only for validation. MKT is a separate source
series, never a sum of the primary types. Amounts are in millions of dollars;
VOL counts issues. These cover rate-eligible issues; rating criteria changed
inside the burn-in. Known 2004 type-specific closures remain missing.

The scoring wall is **2008-12-26**. Post-wall XML observations retain only dates,
series and validity: their amount/count strings are never converted to numbers.
RATES contributes IDs only. CSV rows are date-filtered before numeric conversion.
Downloading, copying, and hashing opaque bytes does not interpret values. The
vintage diff reports value changes only through the wall. Post-wall validity
summaries are structural. Weekly builders and scoring require an issued OOS
Provenance to cross the wall.

OOS requires `prereg/APPROVAL_fed_cp_ot.txt` written by Jared, containing the
pinned PIN.txt SHA256, **and** its `APPROVAL_SHA256` pinned in a reviewed commit; it defaults to None. The JSON design flag
must remain false: it is a record, not a switch. This PR's `run_oos()` always
stops at its unimplemented-harness check after approval and before logging any
trial. It does not burn the three confirmatory trials.

Release timing uses the next weekday at 13:00 America/New_York (DST-aware),
without a holiday calendar; actual posting is not guaranteed. Planned pulls are
13:30 ET with retries until 18:00 ET. Scheduling is external to this CLI; each
fetch has bounded exponential retries. Missing days are never forward-filled.
The provisional view is separate from forecasts. The app is a burn-in
placeholder and has no scored or live forecast.

Preflight order is: verify all seven file hashes, verify PIN references and design
semantics (including the fixed trial count **3**), then verify approval for OOS.
Only then is an immutable Provenance issued, recording the repo-relative prereg
directory. `run_oos` next checks harness implementation, logs the three trial
configurations, and only then loads data. The current stub stops before logging.
