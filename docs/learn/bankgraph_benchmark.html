BankGraph: our own relational benchmark

Learning note + benchmark spec · Nov 3, 2026 · Prepared for Jared · Data: "Bank forecasting datasets" and "BHCF 2008-2017" Drive folders, plus FFIEC HMDA reporter panels · Companion to KumoRFM on NVIDIA NIM · Not investment advice.
Summary. We built five temporal prediction tasks over a linked database of banks, branches, holding companies, mortgage lenders, and complaint companies, using only data from our Drive. Every join was measured. Train/val/test splits are fixed by date, and a sealed holdout is never written to disk by default. On validation, relational aggregates clearly helped one task (branch closure, +0.068 AUC, CI excludes 0) and gave a small gain on holdco-state deposit growth (MAE −0.0011). On bank-deposit decline and complaint spikes, relational features did not help single-table LightGBM. The mortgage-share task is near chance for every baseline. No Kumo or TRACE run has been made on this benchmark; test and holdout labels are untouched.

1. Why our own benchmark

Public benchmarks such as RelBench are used in model development, so headline numbers on them may not transfer. A benchmark built from our own data, with tasks and comparison bars fixed before any challenger runs, gives a fairer test of KumoRFM, and later TRACE, against simple baselines.

Leakage rules

  1. Features use only rows whose availability date (time column + publication lag) is on or before the cutoff.
  2. Labels look strictly after the cutoff.
  3. Peer aggregates are leave-one-out.
  4. Bank→holdco, LEI↔RSSD, and the complaint-company name map are treated as time-invariant in v0.1. This is a documented approximation; the FFIEC NIC relationships file would remove it.
  5. Test labels are stored in a separate file. Holdout rows are written only with RELBENCH_UNSEAL=1, for one final, announced run.
  6. LightGBM hyperparameters are fixed in advance (400 trees, lr 0.03, 31 leaves, min_child 50, subsample/colsample 0.8, seed 0; L1 loss for regression).

5. Metrics and pre-registered comparison bars

AUC for classification and MAE for regression, each with a 95% entity-cluster bootstrap CI (B=500, or 200 when validation has more than 50k rows).

  • A challenger beats a task only if, on test, challenger − lgbm_relational has a paired 95% CI that excludes 0 in its favor. It ties if the CI covers 0 and loses if the CI excludes 0 against it.
  • The headline is a count of wins, ties, and losses across T1–T5, with no averaging across metrics.
  • Challengers get the same tables and cutoffs, with no test or holdout labels in context.
  • T4 is reported with low weight, because all baselines are near AUC 0.5 on validation.
  • The holdout is opened once, after test results are recorded.
